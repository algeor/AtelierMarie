## Key Design Patterns Documented

### 1. Thin Routes, Fat Services
```
Route layer:   HTTP parsing → call service → HTTP response
Service layer: Business logic, testable, no HTTP
```
Example in ONBOARDING.md + CLAUDE.md

### 2. Session-First Identity
```
Anonymous user → Session cookie UUID
Optional login → Session.user_id + JWT
Cart follows session, not user
```
Explained in ARCHITECTURE.md + API.md

### 3. Layer Separation (E-commerce vs Analytics)
```
Layer 1 (Postgres): Checkout, orders, payments → <200ms, must work offline
Layer 2 (DuckDB):   Events, analytics, ML → async, optional, can fail
Layer 1 NEVER imports Layer 2
```
Explained in ARCHITECTURE.md + CLAUDE.md (hard blocker in code review)

### 4. Money as Integer Cents
```
EUR 35.00 = 3500 cents (int)
Display: price_cents / 100 EUR
All: prices, shipping, discounts, totals → cents
```
Why: No floating-point errors. Documented in DATABASE_SCHEMA.md

### 5. Order Items Are Immutable Snapshots
```
At checkout: Insert order_items (product_name, price_cents) frozen in time
Never update order_items after creation
If product price changes, old orders still show original
```
Documented in ARCHITECTURE.md + DATABASE_SCHEMA.md + CLAUDE.md

### 6. Stock Validation at Add, Not Just Checkout
```
User adds to cart → check stock immediately → 409 if out of stock
Don't let user think they can buy what's already sold
```
Documented in ARCHITECTURE.md + API.md (Add to Cart → 409 Conflict)

- [ ] New endpoint added to code? Update `docs/API.md` + `ARCHITECTURE.md` if it changes the system picture
